# 本地学习数据

所选数据目录原有课件文件夹保持不变。程序另建 `_chillpass-data`：

- `courses.json`：课程、解析文本、考点、关卡与学习进度。
- `quiz-progress.json`：逐题作答与归档记录。
- `wrong-questions.json`：错题本。
- `conversations.json`：Athena 会话名称、所属课程、聊天消息及每个会话独立的记忆（聊天存储格式 v2）。
- `current-conversation.json`：当前会话 ID，切换时不重写全部聊天。
- `athena.json`：Athena 模型偏好及旧版全局记忆/技能归档；归档不再自动注入对话。

Athena 的会话按课程分组。会话固定读取所属课程的课件，不随左侧当前课程切换；课程删除后仍保留会话，但不借用其他课程的课件。每个会话的宪章记忆、自动记忆及记忆导入/导出/清空均独立，新会话只使用内置规则的独立副本。

旧聊天首次加载时升级为 v2：根据消息中唯一的课程 ID 归组；混合课程或没有课程标记的旧会话进入“通用 / 历史未归组”，不猜测归属、不删除消息。旧全局记忆仍在 `athena.json`，不复制给每个会话，避免跨课程泄漏；如确有需要，可将原有 Athena 导出的记忆 JSON 显式导入某个会话。迁移沿用保存前备份及版本冲突保护。
- `backups/`：首次迁移前的浏览器原始副本，以及每次更新前的硬盘旧版本。备份目前不自动删除，可占用额外磁盘空间。

文件为带版本标识、修订号和 SHA-256 校验的 JSON，不建议手工编辑。API key、通用界面设置仍保存在浏览器，不包含在该目录中。原来存于 IndexedDB 的课件仍需通过存储设置中的文件迁移功能复制到硬盘；本次不会删除它们。

## 启动与迁移

必须运行新版本地后端。首次用原浏览器打开新版时，先备份浏览器对应数据，硬盘缺少的项目才会导入；若硬盘已存在数据，硬盘为准，浏览器不同的旧副本会先备份。所有学习数据就绪后才挂载界面。换浏览器可恢复学习数据，但需要重新配置 API key。

浏览器仍保留缓存和未完成保存的队列。失败时页面显示错误并重试；尚未保存时关闭页面会提示。不要在保存失败时清除浏览器数据。多个窗口写入同一项目时采用修订检查，不静默覆盖冲突；冲突双方数据保留，需先备份并选择保留版本。

## 更换目录

先提交当前待保存修改，再复制并校验学习数据，最后更新目录配置。目标存在不同数据则拒绝覆盖。旧数据目录保留，原课件不随此操作移动，旧路径继续可读。数据复制中断不会切换配置，可重试。

## 备份与恢复

备份时先退出程序，将整个数据目录连同原课件复制到安全位置。恢复时同样先退出程序；选择 `backups` 中需要的版本，保留当前文件副本，再恢复为对应主文件名。损坏文件会阻止启动，不会用空状态覆盖。

`.write-lock` 用于进程间防止同时写入。若程序被强行终止留下锁，只能在确认所有 ChillPass 实例均已退出后清理这个空目录，再重启。不要在写入过程中删除锁。

“清除学习数据”也会清除硬盘上的课程/答题/错题当前数据，并保留历史备份；不会删除 Athena 聊天或自动销毁备份。
